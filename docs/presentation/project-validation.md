## 검증 절차

1. 방문객 3명 이상·가맹점 담당자 2명 이상을 확보한다. 관리자 카드 출력은 준비자가 수행한다.
2. 같은 시나리오·정보 조건의 개별 안내 화면과 패스 화면을 순서 교차 제시한다. 아래 과제를 역할에 맞게 수행하고 결과는 화면별로 구분한다.
3. [검증 기록](#검증-기록)을 남긴다. 중대 오해는 수정한 뒤 같은 과제로 재검증하고 결과를 기록한다.

## 검증 과제

| 역할 | 과제·연결할 문제 | 관찰·질문 |
| --- | --- | --- |
| 방문객 | 갯골 등 관광지 한 곳에서 시작해 여행 구성 — 체험 연결 | 여행 생성·추천 담기·순서 변경을 수행한다. 처음 알고 있던 장소와 새로 발견한 후보를 구분해 말하게 하고, 추가 카드 선택 여부·종류를 기록한다. |
| 방문객 | 함께 갈 행사·음식점/카페 비교 — 지역 상권 연결 | 후보의 위치·출처를 찾고 선택 이유를 설명하게 한다. 직선거리를 실제 이동거리·시간으로 오해하는지 확인한다. |
| 방문객 | 아이와 함께 가는 상황으로 후보 탐색 — 아동 활동 발견 | 동반 유형·추천 이유·행사 날짜를 찾게 한다. 추천만으로 안전·연령 적합·접수 가능을 보장한다고 이해하는지 확인한다. |
| 방문객 | 주차 또는 야간 이용 조건 확인 — 방문 전 정보 확인 | 공식 출처·확인일·미확인 조건을 찾고 방문 전에 어디서 무엇을 확인할지 설명하게 한다. 정보 없음과 이용 불가를 구분하는지 확인한다. |
| 방문객 | 음식점 안내와 혜택 상세 비교 — 이용 조건 비교 | 위치·비용·예약 조건을 찾게 한다. 공식 지정 업소에 자동으로 할인·제휴가 있다고 오해하는지 확인한다. |
| 방문객·가맹점 담당자 | 혜택 선택·제시·사용·결과 확인 — 이용 조건 이해 | 방문객은 혜택을 선택하고 코드를 제시하며, 담당자는 조건을 확인해 사용 처리한다. 각자 결과를 찾고 여행 패스와 혜택 이용권의 차이를 설명하는지 확인한다. |
| 방문객 | 여행 후 메모·방문 기록 저장·보관·재조회 — 경험 회상 | 기억에 남는 경험을 메모하고 아카이브에서 다시 찾게 한다. 여행 기록과 혜택 피드백의 차이를 설명하게 한다. |
| 방문객 | 관리자가 출력한 카드의 QR로 장소 다시 찾기 — 경험 회상·전달 | 휴대전화로 공개 안내·출처를 열게 한다. 개인정보 노출 없이 다른 여행 카드 탐색으로 이어지는지 확인한다. |

## 검증 기록

| 구분 | 기록할 내용 |
| --- | --- |
| 수행 조건 | 익명 참여자 번호·역할·시나리오·제시 화면·제시 순서. 가족 시나리오 수행 경험은 실제 가족 사용성 검증과 구분 |
| 과제 결과 | 완료 여부·소요 시간·도움 요청·오해, 과제별 관찰 내용 |
| 수정·재검증 | 중대 오해와 수정 내용, 같은 과제의 재검증 결과 |
| 주관적 응답 | 종료 시 다시 이용할 의향과 사용자 의견. 관찰 결과와 구분 |

발표에는 실제 수행한 대상·인원·방법·결과만 사용한다. 미수행 과제나 미확보 측정값을 완료·효과로 표시하지 않는다.

## 검증 한계

추가 장소 선택 수와 QR 접속 성공은 관찰 결과이며 실제 방문·소비·재방문의 증거로 해석하지 않는다. 체류시간·실제 재방문·매출 효과는 화면 검사만으로 확인할 수 없다. 효과 표현은 [공통 요구사항](../func-specs/01-common.md#범위)을 따른다.
