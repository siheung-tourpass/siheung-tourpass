# 최종 발표 준비 기준 — 시흥 투어패스

[문서 안내](../../README.md#관련-문서) · [지역 문제와 사용자 검증](project-validation.md)

## 발표·제출 조건

| 항목 | 기준 |
| --- | --- |
| 제출물·시간 | 발표자료만 제출(보고서 미첨부), 발표 최대 10분(시연영상 재생시간 제외). |
| 시연·발표 영상 | 핵심 문제 해결 시연영상(1~2분 권장, 음성·자막 포함)과 전체 발표영상 링크·QR을 목차에 구분 배치. |

## 발표의 핵심

발표자료만으로 **시흥시 문제 → 기존 서비스 한계 → 해결 기능 → 구현·검증 결과 → 활용 방안**이 드러나야 한다.

| 심사기준 | 배점 | 자료가 답해야 할 질문 |
| --- | --- | --- |
| 지역연계성 | 20점 | 왜 시흥시에서, 누구에게 필요한가? |
| 문제해결성 | 20점 | 어떤 불편을 어떤 기능으로 해결했고 효과를 어떻게 확인했는가? |
| 창의성 | 20점 | 기존 공공·유사 서비스 대비 개선·연결 지점은 무엇인가? |
| 완성도 | 20점 | 실제 구현 범위와 작동 확인 결과는 무엇인가? |
| 정책활용가능성 | 20점 | 시흥시 어느 기관·업무에 어떻게 도입·운영할 수 있는가? |

## 발표자료 구성

| 순서 | 내용 | 필요한 근거·화면 |
| --- | --- | --- |
| 0 | 목차·영상 안내 | [발표·제출 조건](#발표제출-조건) 링크·QR코드 |
| 1 | 팀·서비스 요약 | 팀·역할·서비스명, 해결 문제 한 문장 요약, 유사 팀 대비 차별점 |
| 2 | 시흥시 필요성 | 대상·불편, 통계·정책·뉴스 출처·기준일, 현장·인터뷰 반영 사항 |
| 3 | 기존 서비스와 개선점 | 기존 서비스 화면·한계 표시 및 개선·연계 비교표 |
| 4 | 해결 방식·핵심 기능 | 핵심 기능 2~3개, `현재 문제 → 개선 방향 → 구현 방법` 연결표·흐름도 |
| 5 | 구현 결과·개발 과정 | 완료·부분 구현·미구현 구분, 개발 화면, 데이터·API 연결 방식 |
| 6 | 서비스 시연 | 로그인 소개 대신 핵심 문제 해결 흐름 영상 |
| 7 | 검증·개선 결과 | [검증 기록](project-validation.md#검증-기록) 실제 결과와 수정 전후 비교 |
| 8 | 시흥시 적용·운영 | 대상 기관·도입 방식·운영/갱신/비용·협의 사실과 제안 구분 |
| 9 | 효과·한계·다음 단계 | 확인한 효과와 기대효과 구분, 한계·개선 방향 |

## 작성·제출 점검

- 촬영 전 관리자 화면에서 실제 관광지·관계를 [승인](../data-collection/tourism-data.md#최초-적재)한다.
- 슬라이드 제목은 주장형 문장으로 쓰고, 그림·화면과 짧은 개조식 설명으로 구성한다.
- 영상 링크·QR 재생 여부와 PPTX 글꼴 포함·PDF 변환 상태를 확인하고 [발표·제출 조건](#발표제출-조건)을 점검한다.
