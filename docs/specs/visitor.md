# 방문객 요구사항

공통 범위·인증·정책·완료 기준은 [공통 요구사항](../../spec.md)을 따른다.

## 화면과 탐색

- 방문객 주 메뉴는 아이콘이 있는 홈·여행 만들기(제작/임시 저장)·내 패스(제작 확정)·여행 기록(사용 완료 아카이브)·프로필 순서다. 설정·로그아웃은 프로필에만 둔다. 관광지·행사·시흥시 공식 지정 음식점/카페는 여행 만들기의 카드 탐색으로 통합한다. 비로그인도 카드 탐색이 가능하며 저장은 방문객 로그인 후 제공한다.

## 기능

### 혜택 이용권

| ID | 구현 조건 |
| --- | --- |
| 1 | 비로그인 목록·상세에 가맹점·지역/위치·혜택·기간·횟수·비용·예약 조건 표시. 화면에 시연용·실제 사용 불가 경고를 표시하지 않는다. 미확인 실제 정보는 `미확인`으로 표시. |
| 2 | 본인에게만 유효 이용권 동시 1개 발급, 예측 어려운 고유 코드·시작/만료 표시. 코드는 URL·로그에 노출 금지. |
| 3 | 본인의 활성/만료/취소 이용권·혜택 잔여·사용 시각/가맹점/결과 조회. |

### 추천·피드백

| ID | 구현 조건 |
| --- | --- |
| 4 | 비로그인도 지역(전체 가능)·복수 테마·동반 유형 1개 선택으로 최대 3곳과 근거 확인. 지역은 필터, 테마·동반은 순위 기준이며 미선택 허용. 빈 결과는 조건 변경 안내, 지역 임의 완화 금지. 계산은 [추천 모델](../tourism-semantics.md) 적용. |
| 5 | 본인 성공 혜택 사용당 평가 1건 작성·수정·삭제. 만족도 1~5·복수 선택 사유(흥미/동반 적합/비용/안내)·선택 의견 500자. 만료·취소 후도 가능; 실패/타인 이력 거부·중복 생성 금지·원문 본인만 공개. |
| 6 | 본인의 현재 피드백만 다음 추천에 반영, 수정/삭제 즉시 반영·재시작 보존. 평가한 장소에 항상 적용; 흥미 또는 사유 없음은 보존 테마가 겹치는 장소에도 적용. 동반/비용/안내만 선택하면 해당 장소만 적용. 장소·테마 동시 일치도 평가당 1회, 적용 경로·사유 설명. 평가 없음은 기본 순위. |

### 여행·행사

| ID | 구현 조건 |
| --- | --- |
| 7 | 관광지·행사·음식점/카페로 개인 여행을 구성·임시 저장·확정한다. 세부 조건은 [여행 구성](#여행-구성)을 따른다. |
| 8 | 장소별 방문일(미래 불가)·선택 메모 500자·선택 만족도 1~5 저장/수정/비우기. 만족도는 방문 표시 후만. 제작 확정 후 본인이 사용 완료로 표시하면 아카이브한다. 아카이브에서도 기록 수정 가능하며 복원 시 제작 확정 상태가 된다. 타인 접근 거부. 본인의 사용 완료(아카이브) 여행에서만 포토카드를 조회하며 복원하면 조회를 차단한다. |
| 9 | 별도 행사 목록 페이지 없이 비로그인 여행 카드 둘러보기와 여행 만들기에 실제 행사 안내 카드를 표시한다. 일정·장소·비용·예약 조건·공식 출처·확인일·검토 상태를 제공하고 한국 날짜로 예정/기간 중/일정 종료를 구분한다. 날짜 검색은 종료일을 포함하며 종료 행사도 카드로 탐색할 수 있다. 검토 대기 행사는 안내 자료로만 공개하고 추천·예약 가능으로 표시하지 않는다. 행사도 개인 여행에 담고 기록할 수 있으며 담기는 예약·접수나 개최 확정을 의미하지 않는다. 사진 이용 조건은 [행사 데이터](../data-collection/events-data.md)를 따른다. |

## 여행 구성

기능 7의 상세 조건이다. 카드 배치·조작·사진 표시는 [디자인 기준](../design.md#여행-만들기)을 따른다.

### 시작과 탐색

- 새 여행은 빈 구성 또는 지정 템플릿로 시작한다. 템플릿은 이름·카드·순서를 미리 채우며 저장 전에는 DB에 생성하지 않는다. 모든 장소가 현재 담기 가능한 템플릿만 제공하고 누락 장소를 임의 대체하지 않는다.
- 관광지·행사·음식점/카페를 같은 카드 보드에서 검색어·종류·지역·행사 날짜로 탐색한다. 지역은 관광지·음식점/카페에만 적용한다. 상세 확인·선택을 제공하고 탐색 조건이 바뀌어도 선택을 유지한다. 카드 섞기는 표시 순서만 바꾸며 선택 목록을 유지한다.
#### 시작 단계

- 테마·지역·행사·직접 찾기 중 시작 방식을 고른다. 테마는 하나를 선택해 관광지 후보를, 지역은 해당 지역의 관광지 후보를 제안받는다. 행사는 날짜로 안내 카드를 찾으며 검토 대기 자료를 추천으로 표시하지 않는다. 관광 추천 결과·조건·점수는 기능 4~6을 따른다.
- 시작 카드 선택 → 덱 구성 → 여행 확인을 별도 화면으로 제공한다. 시작 카드는 한 장을 고른 뒤 확인한다. 템플릿·기존 제작 중 여행은 덱 구성부터 연다.
- 이전 단계로 돌아가도 선택·순서·입력을 보존한다. 시작 카드를 다시 고르면 첫 카드만 교체하며, 덱에서 모두 빼도 현재 단계를 유지한다.

#### 이어 담기

- 마지막 선택 카드의 대표 좌표에서 미선택 카드를 직선거리순으로 표시한다. 실제 이동거리·시간·최단 경로는 추정하지 않는다.
- 좌표 미확인 후보는 뒤에 두며 기준 카드의 좌표가 없으면 같은 지역을 우선한다. 행사 지역은 공개 관광지와의 기존 장소 연결로 판정하고 연결이 없으면 미확인으로 둔다.

#### 안내 자료

- 음식점/카페 카드는 시흥시 공식 지정 목록의 근거·확인일·자료 기준일을 표시한다. 관광 추천 점수·혜택·제휴와 연결하지 않으며 기존 여행의 가맹점 카드는 보존한다. 지정 근거·분류·미확인 정보는 [음식점 데이터](../data-collection/dining-data.md)를 따른다.
- 관광지 선택 후 행사·음식점/카페도 함께 비교하도록 안내한다. 가족 이용자는 세부 조건의 동반 유형과 추천 근거를 확인하도록 안내한다. 실제 관광지 상세에는 [방문 조건 검토 항목](../data-collection/tourism-data.md#방문-조건)을 확인할 안내를 제공하고, 음식점 안내와 혜택 제휴를 구분한다.

### 저장과 상태 변경

- 선택 목록·순서를 확인한 뒤 이름 100자·선택 날짜로 저장한다. 선택 카드와 여행은 원자적으로 저장한다. 기존 API의 빈 여행 생성과 여행 이름·날짜 수정은 유지한다.
- 제작 중 패스는 같은 카드 보드에서 선택·순서·이름·날짜를 복원해 수정·임시 저장·확정·삭제한다. 빈 임시 저장은 허용하지만 확정에는 카드 1개 이상이 필요하다.
- 확정 상태에서는 구성 변경·삭제를 금지한다. 본인이 제작 중으로 되돌리면 기존 구성·방문 기록·이용권 연결을 유지한 채 다시 수정·삭제할 수 있다. 사용 완료·복원과 방문 기록은 기능 8을 따른다.

### 담기와 보존

- 활성 지역의 승인 장소 또는 검토 대기 실제 관광지 중 활성 장소를 담을 수 있다. 중복을 막고 선택 삭제·위/아래 이동을 제공한다.
- 행사·공식 지정 음식점/카페는 공개 안내 자료에서 여행에 담을 수 있다.
- 담을 때 카드 종류·고유 키·이름·지역·위치·실제/시연 구분을 보존한다. 이후 비활성화·검토 상태 변경에도 본인 조회를 허용한다.

## 관광지 피드백

| ID | 구현 조건 |
| --- | --- |
| 10 | 로그인한 방문객은 공개 탐색 가능한 관광지에 만족도 1~5와 선택 의견 500자를 남긴다. 방문객·관광지당 현재 평가 1건을 저장하며 본인만 수정·삭제·원문 조회할 수 있다. 방문 인증이나 혜택 사용을 요구하지 않는다. |

- 관리자에게는 [관광지 피드백 통계](admin.md#관광지-피드백-통계)만 제공한다. 여행 기록·혜택 평가와 별도로 보존하며 추천에는 반영하지 않는다. 비공개 전환 후에도 본인 API 조회·삭제와 통계는 유지한다.
