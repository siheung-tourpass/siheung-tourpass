## 공통 규칙

카드의 입체감은 공통 표면 그림자를 사용하며, 선택 표시는 선명한 안쪽 테두리로 구분한다. 번짐 없는 두꺼운 외곽 그림자는 사용하지 않는다.

색·크기·곡률·여백·글꼴의 값은 [토큰](../frontend/assets/tokens.css), 적용 방식은 [스타일](../frontend/assets/style.css)을 원본으로 관리한다. 이 문서는 화면 구성과 상호작용 기준을 설명한다.

- 초록 강조색·중립 회색 바탕·시스템 한국어 글꼴을 사용한다. 모바일은 한 열을 기본으로 하고 제목·설명·주요 행동의 위계를 분명히 한다.
- 둥근 연속 곡면과 밝은 가장자리를 불투명 표면으로 표현하고, 뉴모피즘의 부드러운 입체감은 낮은 농도의 짧은 그림자로만 표현한다. 카드·메뉴·팝오버는 같은 표면과 그림자 체계를 공유한다. 배경 블러는 쓰지 않으며 그림자·사진 틴트·대화상자 바깥 배경에만 투명도를 허용한다.
- 입력은 불투명한 옅은 중립 표면과 명확한 경계를 사용한다. 주요 행동은 강조색 채움, 보조 행동은 흰 표면, 위험 행동은 오류색과 문구로 구분한다. 선택·오류는 색만으로 전달하지 않는다.
- 입력·주요 버튼 높이는 52px 이상이다. 상시 라벨·키보드 포커스를 제공하고 본문 대비 4.5:1, 입력 경계·포커스 대비 3:1 이상을 유지한다. 입력 오류는 input·select·textarea에 같은 기준으로 표시한다.
- 자동 등장 효과는 쓰지 않는다. 짧은 누름 반응을 사용하며 모션 감소 설정에서는 이동 효과를 끈다. 320·375·414·768px에서 가로 넘침과 조작 영역을 확인한다.

## 공통 화면 틀

- 고정 상단의 프로젝트명을 중앙에 두고 좌우에 같은 조작 영역을 확보한다. 왼쪽은 상세·하위 화면의 돌아가기 버튼에만 사용한다. 본문·앵커·키보드 포커스가 상단에 가리지 않게 한다.
- 하단 내비게이션은 화면 가장자리에서 띄운 불투명 캡슐로 표시한다. 본문 여백과 기기 안전 영역을 확보하고 아이콘·한 줄 라벨을 중앙 정렬한다. 현재 메뉴는 배경·글자색·굵기로 구분하며 상단 표시선은 쓰지 않는다.
- 메뉴와 강조 영역은 같은 `--radius-navigation` 윤곽을 사용한다. hover에도 같은 윤곽을 유지하고 키보드 포커스는 메뉴 안쪽에 표시한다. 공통 규격을 바꿀 때 기능별 카드 비율·동작을 유지한다.
- 보조 조작 영역은 44px 이상으로 제공하고 선택 입력에는 실제 체크박스를 사용한다.
- 팝업은 화면 가로·세로 중앙에 표시한다. 최대 폭 640px·좌우 여백 16px, 내비게이션과 같은 곡률·표면·그림자와 공통 배경 음영을 사용한다. 제목과 닫기를 상단에 두고 긴 내용은 내부에서 스크롤한다. 닫기·Esc와 실행 버튼으로의 포커스 복귀를 유지한다.

## 카드 방향

- 여행 패스·혜택 이용권·상품·여행 템플릿은 명함 느낌의 가로형 카드다. 절취선·파인 모서리·분리된 우측 구획은 사용하지 않는다. 모바일에서도 정보는 왼쪽, 상태·수량·주요 동작은 오른쪽에 둔다. 긴 설명이 펼쳐지면 높이를 늘려 내용을 보존한다.
- 관광지·행사·가맹점·혜택 조건·장소별 방문 기록은 세로형 카드다. 사진 또는 제목 아래에 정보를 배치하며 기본 가로:세로 비율은 2:3이다. 상세·폼·출처가 길면 높이를 늘리고 탐색 덱만 고정 비율과 내부 스크롤을 사용한다.
- 대상에 따라 방향을 결정한다. 패스 상세에서도 개별 장소·혜택 카드는 세로형을 유지한다. 카드 너비·비율은 [토큰](../frontend/assets/tokens.css)을 공유한다.

## 화면 구성

상단 브랜드 → 제목·설명 → 입력·결과 순서로 구성한다. 공통 헤더·파비콘·모바일 홈 화면 아이콘은 `frontend/assets/tourpass-icon.png`를 사용한다. 정상·빈 결과·실패 상태에서 다음 행동을 안내한다. 방문객 메뉴와 여행 상태의 대응은 [요구사항](specs/visitor.md#기능)을 따른다. 관리 화면도 같은 화면 틀 안에 메뉴·목록·편집 폼을 배치한다.

### 관리자

[관리자 요구사항](specs/admin.md#관리자-작업과-카드-출력)의 홈 정보를 검토 대기·업무 바로가기·공개 화면 확인 순서로 배치한다. 관광 관리의 카드 선택 목록은 방문객 탐색 카드의 2:3 앞면·종류 배지·하단 정보 패널을 공유하며 사진·종류·이름·위치를 표시한다. 이름·위치 검색과 관광지/행사/음식점/카페 필터를 제공하고 결과를 나누어 표시한다. 사진은 원본 비율을 유지하며 출처는 연결된 상세 안내에서 확인한다.

- 관광 관리: 지역·테마·관계는 접힌 보조 메뉴에 둔다.
- 혜택 관리: 상품 카드에 연결 가맹점·혜택을 표시한다. 편집 폼은 기존 카드 또는 새 자료 등록을 선택한 뒤 표시한다. 장소·가맹점은 세로형, 상품은 가로형이다.
- 카드 출력: 관광 관리 카드의 출력 버튼 → 문구·수량 설정 → 미리보기·인쇄. 출력 설정에서는 카드 목록을 반복하지 않고 관광 관리로 돌아가 다른 카드를 선택한다. QR 주소·인쇄 기준은 접힌 설정에 둔다.
- 편집은 넓은 화면에서 목록·폼 두 열, 모바일 한 열이다. 선택 상태와 필수 입력을 표시하고 저장·검토·비활성화를 구분한다. 비활성화는 영향 안내를 펼친 뒤 실행한다.
- 인쇄 시 탐색·메뉴·폼을 숨기고 [굿즈 규격](specs/admin.md#관리자-작업과-카드-출력)에 맞춰 배치한다. 사진 원본 비율과 QR 흰 여백을 보존한다.

### 관광지 피드백

관광지 상세 아래에 만족도 선택·선택 의견·저장·기존 평가 삭제를 배치한다. 비로그인은 로그인 링크를 제공하고 저장·삭제 후 결과를 안내한다. 독립 통계 메뉴의 피드백 통계는 관광지별 응답 수·평균과 점수별 건수를 카드로 표시해 모바일에서도 읽을 수 있게 한다.

### 랜딩·로그인

랜딩은 관광지 사진·서비스 소개·로그인·공개 카드 탐색 순서로 안내한다. 로그인은 아이디·비밀번호와 오류 안내·둘러보기 링크만 제공하며 계정 역할을 사용자가 선택하지 않는다. 두 화면은 공통 브랜드와 스타일을 사용한다. 메뉴 노출·로그인 이동은 [공통 인증](../spec.md#공통-화면과-인증)을 따른다.

### 홈

홈 제목·안내 문구 아래에 관광지 사진을 16:9로 채워 표시한다. 사진 아래의 사진 출처 버튼으로 공통 중앙 팝업을 열어 설명과 [공통 이미지 표기 항목](data-collection/common.md#이미지)을 제공한다. 홈 사진은 지연 로딩하지 않는다.

- 홈은 새 여행·제작 중 여행·확정 패스·행사 일정을 카드 대시보드로 제공한다. 새 여행은 주요 카드로, 행사는 별도 가로 카드로 구분하고 카드 전체를 하나의 링크로 사용한다.
- 방문객에게 본인의 제작 중·확정 개수와 최근 생성한 제작 중 여행 이름을 표시한다. 비로그인은 별도 랜딩을 제공하며 다른 역할에는 개인 카드를 숨긴다.
- 좁은 화면에서는 한 열로 전환하고 이용 방법은 기본 접힌 안내로 제공한다. 방문객 흐름에서는 여행 구성·기록을 우선한다. 여행 패스와 시연 혜택 이용권을 구분하고 시연 표시·추천 근거를 유지한다.

### 패스 목록·표지

- 제작 중·내 패스·여행 기록은 상태·이름·날짜·선택 카드 수를 구분한 가로형 패스를 공유한다. 템플릿과 상세도 같은 표지를 사용한다.
- 선택 순서에서 사진이 있는 첫 카드의 이미지를 오른쪽에 배치한다. 사진이 없으면 단색으로 표시하고 제목·상태·날짜·동작은 불투명 표면에 둔다.
- 카드 전체를 누르면 제작 중은 이어 만들기, 확정·아카이브는 상세로 이동한다. 별도 열기 버튼은 두지 않는다. 카드 전체에 키보드 포커스를 표시하고 삭제·출처 조작은 이동 링크와 분리한다.
- 삭제·사용 완료·복원은 정보 영역 오른쪽 위의 동작 아이콘과 확인 팝오버로 실행한다. 구성·사진 출처 버튼은 정보 영역 아래에 고정한다. 팝오버가 카드 크기를 바꾸거나 사진 위에 버튼이 겹치지 않게 한다.
- 팝오버 배치는 [공통 화면 틀](#공통-화면-틀)을 따르며 바깥 클릭으로도 닫는다. 사진 출처 항목과 이용 조건은 [이미지 기준](data-collection/common.md#이미지)을 따른다.
- 방문객 홈의 새 여행 만들기 카드와 제작 중 목록의 새 여행 만들기는 빈 구성·템플릿을 선택하는 팝오버를 연다. 준비되지 않은 템플릿은 대기 이유를 표시하고 선택을 막는다. 저장 시점·템플릿 조건은 [여행 구성](specs/visitor.md#여행-구성)을 따른다.

### 여행 만들기

시작 카드 고르기 → 덱 만들기 → 여행 확인의 세 화면을 명시적으로 이동한다. 여행 확인에서 이름·선택 날짜를 입력하고 임시 저장 또는 제작 확정한다. 제작 중도 같은 보드에서 이어 만든다. 삭제는 펼친 경고에서 확인 후 실행한다.

#### 탐색·선택

- 상단에는 시작 카드·덱 구성·여행 확인의 현재 단계를 표시하고, 전환 시 화면 제목으로 포커스를 옮긴다. 테마 칩은 첫 카드 선택 단계 안에 라디오 그룹으로 두고 ‘테마 없이 둘러보기’를 제공한다. 첫 카드 선택 화면은 테마와 카드 탐색만 제공하며 ‘이 카드로 시작’으로 덱 구성에 진입한다. 덱 구성의 ‘시작 카드 변경’으로 돌아가면 테마 선택을 복원한다. 검색과 세부 조건은 ‘직접 찾기’에 모아 시작 카드 화면에서는 접고 덱 구성에서는 펼친다. 지역·행사 날짜·동반 유형은 그 안의 접힌 ‘세부 조건’에 둔다. [탐색 기준](specs/visitor.md#시작과-탐색)에 따라 담은 마지막 카드의 이름을 기준으로 직선거리순 탐색을 안내하고 카드 앞면에 거리를 표시한다. 대표 지점 간 거리이며 실제 이동거리와 다름을 설명한다. 좌표 미확인 후보는 거리를 추정하지 않고 뒤에 둔다. 기준 좌표가 없으면 같은 지역 우선 안내로 전환한다. 선택 카드·저장 순서는 유지하며 자동으로 넘기지 않는다.
- 가로 스크롤 스냅·터치 스와이프·마우스 드래그·이전/다음 버튼·방향키로 탐색한다. 중앙 카드와 양옆 카드의 크기·강조를 구분하고 중앙에서의 거리에 따라 회전·깊이를 바꾸되 모션 감소 설정에서는 끈다.
- 관광지·행사·음식점/카페는 같은 선택·상세·저장 조작을 제공한다. 카드 클릭으로 선택·해제하며 우측 상단 더하기를 체크로 바꾸고 초록 테두리·밝은 안쪽 선·접근성 선택 상태를 함께 갱신한다. 선택 후 자동으로 다음 카드로 넘기지 않는다.
- 상세 버튼으로 카드를 뒤집고 다른 카드로 이동하면 앞면으로 복귀한다. 앞·뒷면 전환 버튼은 우측 하단에 두고 설명과의 간격을 좁힌다.
- 탐색 안내에서 관광지·행사·음식점/카페를 함께 고르는 흐름을 설명하고, 동반 유형 선택 바로 아래에 가족 체험의 조건 확인을 안내한다. 실제 관광지의 방문 전 확인 안내는 카드 뒷면·장소 상세·출력 QR 안내 페이지에서 같은 조각을 사용한다.

#### 카드 정보·사진

- 카드 앞면 상단에는 선형 아이콘과 종류를, 하단 흰 정보 패널에는 이름 → 위치·행사 날짜 → 구분선이 있는 상세 버튼을 배치한다. 검토 상태·출처·확인일·사진 이용 조건은 뒷면의 스크롤 영역에 제공한다.
- 세로형 비율은 [카드 방향](#카드-방향)을 따른다. 관광지 사진 배경에는 약한 틴트를 적용하되 종류·이름·위치·상세 버튼은 불투명 흰 표면과 진한 글자로 표시한다.
- 행사·음식점/카페 사진은 종류 배지와 정보 패널 사이 독립 영역에 배치한다. 표시·편집 허용 범위는 [행사](data-collection/events-data.md#이미지)·[음식점 이미지 기준](data-collection/dining-data.md#이미지)을 따른다. 사진이 없는 행사·음식점/카페·기존 가맹점은 같은 옅은 초록 바탕과 종류별 선형 그림을 사용하며 이미지 준비 문구는 표시하지 않는다.

#### 선택 목록·저장

- 덱 구성에는 담은 목록·순서 조작을 본문에 표시하고 첫 카드에 시작점을 표기한다. 여행 확인은 탐색 보드를 숨기고 전체 순서·이름·날짜·저장 동작을 본문에 표시한다.
- 단계 이동 바는 하단 메뉴 위에 두고 선택 수와 다음 단계 동작을 표시한다. 빈 덱도 여행 확인에서 임시 저장할 수 있다. 메뉴와 최대 폭·좌우 여백·안전 영역을 공유하되 안쪽 여백은 별도로 유지한다. 본문·포커스를 가리지 않는다.
- JavaScript가 없으면 카드 목록과 저장 폼을 모두 표시한다. 검토 대기 관광지의 담기·저장 조건은 [요구사항](specs/visitor.md#여행-구성)을 따른다.

### 정보와 행동의 우선순위

- 화면마다 주요 행동 하나를 강조한다. 초기화·다른 대상 조회는 보조 동작으로, 삭제·취소는 위험 동작으로 구분한다.
- 여행 구성은 ‘여행 만들기·담은 카드’, 혜택 인증은 ‘혜택 이용권 코드’로 표현해 두 기능을 구분한다.
- 기록 입력을 먼저 보여주고 추천 반영 설명·이용권 연결 이력은 기본 접힌 안내로 제공한다. 유효기간·사용 차감 조건은 실행 전에 노출한다.
- 담당자의 혜택 사용 확인·사용 이력은 내용 높이에 맞춘 간결한 카드로 표시한다.
- 새 만족도는 미선택 상태에서 시작한다. 저장된 평가는 기존 선택을 유지한다.

### 여행 기록·상태 변경

- 기록 입력은 좌우 스크롤·스와이프·이전/다음 버튼·방향키로 탐색한다. 이동 중 입력을 유지하고 저장 후 같은 카드로 복귀한다. JavaScript가 없으면 기록 폼을 목록으로 제공한다.
- [허용된 상태 변경](specs/visitor.md#저장과-상태-변경)은 패스의 상태 팝오버에서 실행하고 변경 후 해당 상태의 목록으로 이동한다.
