# 이슈·PR 작성 규칙

## 이슈

- 제목은 `[Bug] 요약`, `[Feature] 요약`, `[Task] 요약` 중 하나로 작성한다. 각각 오류, 기능 제안, 문서·정리 등 기타 작업에 사용한다.
- 본문에는 현재 문제와 원하는 결과를 적는다. 버그는 재현 방법·기대한 동작·실제 동작·실행 환경을 함께 적는다.
- 관련 요구사항이 있으면 링크하고, 해당하지 않는 템플릿 항목은 삭제한다.

## PR

- 제목은 `type: 요약`으로 작성한다. type은 `feat`(기능), `fix`(버그 수정), `docs`(문서), `refactor`(동작 변경 없는 구조 개선), `test`(테스트), `chore`(설정·도구 등 기타 작업)를 사용한다.
- 예: `feat: 여행 기록 검색 추가`, `fix: 이용권 만료 시 사용 차단`.
- 하나의 목적을 다루고, 본문에 변경 이유·내용과 검증 방법·결과를 적는다. 검사를 실행하지 못했다면 이유를 적는다.
- 이슈를 해결하면 `Closes #123`, 참고만 하면 `Refs #123`으로 연결한다. 화면을 변경했다면 스크린샷을 첨부한다.
- 필요한 문서·설정·마이그레이션 변경을 함께 적고, 해당하지 않는 템플릿 항목은 삭제한다.
