# 공통 요구사항 — 시흥 투어패스

[README](../../README.md) · [기술 구조](../03-tech/01-architecture.md) · [REST API 명세](../03-tech/api.md) · [테스트 명세](../04-test/README.md)

## 범위

시흥시 방문객·가맹점 담당자·관리자용 공모전 시연 웹서비스다. 방문객이 온톨로지 추천과 본인 피드백을 바탕으로 여행을 계획하고 투어패스를 구매해 혜택을 이용·기록한다. 실제 제휴·결제 없이 실제 관광지와 시흥시 지정 음식점·카페를 가상 가맹점으로 사용한다. 문제 가설과 검증 과제는 [지역 문제와 사용자 검증](../presentation/project-validation.md)을 따르며, 체류·재방문·소비 증가는 검증 전까지 기대 효과로만 표현한다.

### 용어

| 구분 | 목적·조건 |
| --- | --- |
| 여행 패스 | 본인 전용 여행 계획·기록(복수 생성, 만료 없음, [여행 구성](02-visitor.md#여행-구성) 적용). 본인 이용권 1개를 연결·해제하며 여행에서 구매 시 자동 연결한다. 이용권 만료·취소 후에도 기록·이력을 유지한다. |
| 투어패스(혜택 이용권) | 가상 가맹점 혜택(각 1회 무료·할인)을 묶은 1일권 상품. 구매는 금액만 확인하는 시연 결제(미청구)다. 초기 시연 자료는 허구 가맹점 A·B와 상품 1종을 사용한다. |

### 제외 범위

사진 공유 · 자동 방문 인증 · 실제 결제/환불/정산 · 실제 제휴 계약 · 예약/교통/문자 · 혜택 인증 QR · 상용 운영 · 자동 동선 · LLM · 외부 지식 그래프.

## 공통 화면과 인증

- 비로그인 `/`는 랜딩(소개·로그인·공개 탐색), `/login`은 로그인 화면이며 둘 다 하단 메뉴를 숨긴다. 로그인 성공 및 로그인 상태의 `/login` 접근 시 저장된 역할에 따라 방문객·관리자는 `/`, 가맹점 담당자는 혜택 사용 화면으로 이동하고, 로그아웃 시 랜딩으로 이동한다. 화면 배치는 [디자인 기준](../02-uxui/01-design.md#화면-구성)을 따른다.
- 카카오 로그인은 최초 인증 시 별도 방문객 계정을 생성하고 이후 카카오 회원번호로 로그인한다(기존 계정 자동 연결·관리자/담당자 권한 부여 없음). 일회성 `state`는 세션에 묶어 5분 후 만료하며 인증 성공 시 세션 ID를 교체한다. 토큰은 저장하지 않고 OAuth 콜백 GET에서 가입·인증을 처리한다.

## 공통 기능

| ID | 구현 조건 |
| --- | --- |
| 1 | 3역할 아이디·비밀번호 로그인(해시 암호) 및 방문객 카카오 로그인. 이용권 발급은 [방문객 요구사항](02-visitor.md#기능) 적용. |
| 2 | 혜택 성공 이력과 잔여 감소를 원자적으로 저장(동시 요청 포함 혜택당 1회). 실패 시 차감·성공 이력 금지(별도 감사 기록 허용). |
| 3 | 전 요청 역할·소유권·CSRF·XSS 방어. 관리자 권한은 [관리자 요구사항](04-admin.md#기능) 적용. |
| 4 | 발급 당시 상품명·기간·혜택·가맹점/지역/위치·비용·예약 조건 보존(상품 변경 시 기존 발급분 불변, 취소·가맹점 비활성화 시 사용 차단). |
| 5 | 실제 장소는 출처·확인일·검토 상태, 허구는 시연 표시([데이터 수집 공통 기준](../data-collection/common.md) 적용). |
| 6 | [README](../../README.md#시작하기)만으로 재현 가능하며 재시작 후 발급·사용·취소·여행·피드백 유지. |

## 정책

- 이용권 기간은 24시간 `[시작, 만료)`(서버 판정·DB UTC·화면 KST)다. 오늘 이후 여행 날짜에서 구매하면 해당 날짜 0시(KST), 그 외에는 즉시 시작한다. 취소되지 않은 본인 이용권과 기간이 겹치면 구매를 거절하며, 비겹침 시 복수 보유를 허용한다. 혜택별 이용권당 1회(재사용 간격 없음).
- 미사용·만료 전·연결 여행 미완료 상태의 본인 이용권만 환불(시연 취소)할 수 있다. 환불 시 취소 상태로 전환하고 여행 연결은 이력을 남긴 채 해제한다.
- 구매 시 상품 가격을 보존하며 0원 상품은 구매를 차단한다. 시연 결제는 결제 수단을 받지 않는다.
- 여행 담기는 예약·발급·사용이 아니며 방문 기록은 방문 인증이 아니다. 일반 관광 만족도는 혜택 피드백·추천 점수에 합산하지 않는다.
- 장소 소개·추천은 실제 영업·예약·이동을 보장하지 않는다. 내 이용권의 사용 가능 표시는 소유권·기간·취소·가맹점 활성·잔여를 재검사한다.
- 추천 승인 조건은 [데이터 적재 기준](../data-collection/tourism-data.md#적재), 장소 사진 표시는 [데이터 기준](../data-collection/common.md#이미지)을 따른다.
- 평가·의견은 주관적 응답으로만 다루며 통계 활용은 [관광지 피드백 통계](04-admin.md#관광지-피드백-통계), 접근성·상태 표시는 [디자인](../02-uxui/01-design.md)을 따른다.
