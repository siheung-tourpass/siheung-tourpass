# 방문객 요구사항 — 시흥 투어패스

[문서 안내](../../README.md#관련-문서)

공통 범위·인증·정책·완료 기준은 [공통 요구사항](01-common.md)을 따른다.

## 공개 탐색

관광지·행사·시흥시 공식 지정 음식점/카페를 여행 만들기의 카드 탐색으로 통합한다. 비로그인도 탐색할 수 있으며 저장은 방문객 로그인 후 제공한다. 메뉴·화면 배치는 [디자인 기준](../tech-specs/02-design.md#역할별-메뉴)을 따른다.

## 기능

### 혜택 이용권

| ID | 구현 조건 |
| --- | --- |
| 1 | 비로그인 목록·상세에 가맹점·지역/위치·혜택·기간·비용·예약 조건을 표시하고 상품 가격은 여행 구성 후 구매 안내에서 표시한다. 화면에 시연용·실제 사용 불가 경고를 표시하지 않는다. 미확인 실제 정보는 `미확인`으로 표시. |
| 2 | 본인에게만 시연 결제로 발급, 예측 어려운 고유 코드·가격·시작/만료 표시. 기간이 겹치는 이용권은 거절한다. 여행에서 구매하면 그 여행에 연결하고 [정책](01-common.md#정책)의 시작 시각을 적용한다. 코드는 URL·로그에 노출 금지. |
| 3 | 본인의 활성/만료/취소 이용권·혜택 잔여·사용 시각/가맹점/결과 조회. |

여행 만들기의 관광지·음식점/카페 카드 중 가맹점에 연결된 카드는 혜택을 표시한다. 여행 확인 단계와 투어패스가 없는 확정 여행에는 담은 카드의 혜택 수가 가장 많은 상품(같으면 가격이 낮은 상품)을 추천한다. 여행 확인 단계에서는 제작 확정과 구매를 한 동작으로 이어 구매 화면으로 이동한다. 연결된 투어패스가 있으면 여행 상세에 코드와 장소별 혜택·사용 여부를 표시한다.

공개 안내는 전체 상품과 거기서 들어가는 이용 가능 시설로 두고, 이용 방법은 홈, 투어패스 유의사항은 구매 화면과 내 투어패스, 여행 패스 유의사항은 여행 상세에 둔다. 상품 목록·상세는 템플릿처럼 포함 혜택과 여행 시작만 제공하고 가격·구매 버튼은 두지 않으며, 비로그인은 로그인으로 안내한다. 기간이 겹치는 이용권이 있으면 구매 화면에서 결제를 막고 이유를 표시한다. 내 투어패스에는 본인 이용권의 코드·남은 시간·혜택 잔여·사용 이력과 제작 확정한 진행 중 여행을 제공하고 발급 후 이 화면으로 이동한다. 메뉴·배치는 [투어패스 안내](../tech-specs/02-design.md#투어패스-안내)와 [내 투어패스](../tech-specs/02-design.md#내-투어패스)를 따른다.

### 여행·행사

| ID | 구현 조건 |
| --- | --- |
| 7 | 관광지·행사·음식점/카페로 개인 여행을 구성·임시 저장·확정한다. 세부 조건은 [여행 구성](#여행-구성)을 따른다. |
| 8 | 장소별 방문일(미래 불가)·선택 메모 500자·선택 만족도 1~5 저장/수정/비우기. 만족도는 방문 표시 후만. 제작 확정 후 본인이 사용 완료로 표시하면 아카이브한다. 아카이브에서도 기록 수정 가능하며 복원 시 제작 확정 상태가 된다. 타인 접근 거부. 본인의 사용 완료(아카이브) 여행에서만 포토카드를 조회하며 복원하면 조회를 차단한다. |
| 9 | 별도 행사 목록 페이지 없이 비로그인 여행 카드 둘러보기와 여행 만들기에 실제 행사 안내 카드를 표시한다. 일정·장소·비용·예약 조건·공식 출처·확인일·검토 상태를 제공하고 한국 날짜로 예정/기간 중/일정 종료를 구분한다. 날짜 검색은 종료일을 포함하며 종료 행사도 카드로 탐색할 수 있다. 검토 대기 행사는 안내 자료로만 공개하고 추천·예약 가능으로 표시하지 않는다. 행사도 개인 여행에 담고 기록할 수 있으며 담기는 예약·접수나 개최 확정을 의미하지 않는다. 사진 이용 조건은 [행사 데이터](../data-collection/events-data.md)를 따른다. |

## 여행 구성

기능 7의 상세 조건이다. 카드 배치·조작·사진 표시는 [디자인 기준](../tech-specs/02-design.md#여행-만들기)을 따른다.

### 시작과 탐색

- 새 여행은 전체 상품에서 투어패스를 고르거나 직접 카드를 골라 시작한다. 상품으로 시작하면 상품명과 포함 혜택의 관광지·음식점/카페를 혜택 순서대로 미리 담고 같은 장소는 한 번만 담는다. 혜택이 없거나 연결된 장소 중 현재 담을 수 없는 곳이 있으면 상품 시작을 막고 이유를 표시하며 임의 대체하지 않는다. 상품 선택만으로 여행을 저장하거나 이용권을 구매·연결하지 않으며 저장 전 카드·순서·이름을 바꿀 수 있다.
- 관광지·행사·음식점/카페를 같은 카드 보드에서 검색어·종류·지역·행사 날짜로 탐색한다. 지역은 관광지·음식점/카페에만 적용한다. 상세 확인·선택을 제공하고 탐색 조건이 바뀌어도 선택을 유지한다.

#### 구성 단계

- 덱 구성 → 여행 확인을 별도 화면으로 제공한다. 새 여행·상품으로 시작한 여행·기존 제작 중 여행 모두 덱 구성부터 연다.
- 덱 구성에서 여행 취향(테마)과 세부 조건의 지역·동반 유형으로 관광 추천을 받는다. 담은 카드가 없으면 추천 관광지를 앞에 두고 근거를 함께 보여 주며, 담기 시작하면 [이어 담기](#이어-담기) 순서를 따른다. 행사는 종류·날짜로 찾으며 검토 대기 자료를 추천으로 표시하지 않는다. 관광 추천 결과·조건·점수는 기능 4~6을 따른다.
- 이전 단계로 돌아가도 선택·순서·입력을 보존하며, 덱에서 모두 빼도 현재 단계를 유지한다.

#### 이어 담기

- 마지막 선택 카드의 대표 좌표에서 미선택 카드를 직선거리순으로 표시한다. 실제 이동거리·시간·최단 경로는 추정하지 않는다.
- 덱 구성·여행 확인에는 담은 카드만 지도에 표시한다. 카드를 담을 때마다 순서 번호와 순서대로 잇는 직선이 늘어나고, 여행 확인에는 최종 구성 전체를 보여 준다. 담은 목록에는 앞 카드와의 대표 지점 간 직선거리를 함께 표시한다. 직선은 방문 순서 표시이며 경로가 아니다. 좌표가 없는 카드는 지도에 표시하지 않고 그 수를 알린다.
- 좌표 미확인 후보는 뒤에 두며 기준 카드의 좌표가 없으면 같은 지역을 우선한다. 행사 지역은 공개 관광지와의 기존 장소 연결로 판정하고 연결이 없으면 미확인으로 둔다.

#### 안내 자료

- 음식점/카페 카드는 시흥시 공식 지정 목록의 근거·확인일·자료 기준일을 표시한다. 관광 추천 점수와 연결하지 않으며, 가상 가맹점으로 연결된 카드에만 투어패스 혜택을 표시한다. 기존 여행의 가맹점 카드는 보존한다. 지정 근거·분류·미확인 정보는 [음식점 데이터](../data-collection/dining-data.md)를 따른다.
- 관광지 선택 후 행사·음식점/카페도 함께 비교하도록 안내한다. 가족 이용자는 세부 조건의 동반 유형과 추천 근거를 확인하도록 안내한다. 실제 관광지 상세에는 [방문 조건 검토 항목](../data-collection/tourism-data.md#방문-조건)을 확인할 안내를 제공하고, 음식점 안내와 혜택 제휴를 구분한다.

### 저장과 상태 변경

- 선택 목록·순서를 확인한 뒤 이름 100자·선택 날짜로 저장한다. 선택 카드와 여행은 원자적으로 저장한다. 기존 API의 빈 여행 생성과 여행 이름·날짜 수정은 유지한다.
- 제작 중 패스는 같은 카드 보드에서 선택·순서·이름·날짜를 복원해 수정·임시 저장·확정·삭제한다. 빈 임시 저장은 허용하지만 확정에는 카드 1개 이상이 필요하다.
- 확정 상태에서는 구성 변경·삭제를 금지한다. 본인이 제작 중으로 되돌리면 기존 구성·방문 기록·이용권 연결을 유지한 채 다시 수정·삭제할 수 있다. 사용 완료·복원과 방문 기록은 기능 8을 따른다.

### 담기와 보존

- 활성 지역의 승인 장소 또는 검토 대기 실제 관광지 중 활성 장소를 담을 수 있다. 중복을 막고 선택 삭제·위/아래 이동을 제공한다.
- 행사·공식 지정 음식점/카페는 공개 안내 자료에서 여행에 담을 수 있다.
- 담을 때 카드 종류·고유 키·이름·지역·위치·실제/시연 구분을 보존한다. 이후 비활성화·검토 상태 변경에도 본인 조회를 허용한다.

## 여행 사진

- 본인의 여행 기록 카드마다 직접 촬영한 JPEG·PNG 한 장을 업로드·교체·삭제한다. 8MB 이하, 최대 1,600만 화소이며 서버가 이미지 내용과 크기를 검사하고 메타데이터를 제거해 저장한다. 사진은 본인만 조회하며 여행 카드 삭제 시 함께 삭제한다.
- 사용 완료 여행의 포토카드는 [공통 출력 규격](04-admin.md#카드-출력)을 사용하고 본인 사진이 있는 카드만 출력한다. 사진이 없으면 여행 기록의 업로드로 안내한다. 개인정보를 포함한 공개 QR은 만들지 않는다.
