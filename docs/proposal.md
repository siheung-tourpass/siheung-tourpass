# siheung-tourpass: 나만의 시흥 여행을 구성하고 간직하는 디지털 투어패스

> 제안서 초안. 팀명은 제안이며 팀원·일정은 미확정으로 4인·8주를 가정한다. [평가 기준](evaluation.md)을 적용하고, 구현 범위의 원본은 [요구사항](../spec.md), 기술·남은 검증은 [계획](../plan.md)이다.

## 1. 프로젝트 개요

시흥의 가고 싶은 장소를 담고, 취향에 맞는 여행을 추천받고, 다녀온 경험을 간직하는 개인 디지털 투어패스다. 여행 전 계획과 여행 후 기록이 같은 패스에 쌓인다. 혜택 이용권은 선택 기능이며 여행 기록의 보존 기간과 분리한다.

- 팀명(안): 이음. 여행 계획과 경험, 다음 방문을 잇는다는 뜻이다.
- 사용자: 시흥 방문객. 가족 당일 방문 상황을 우선 검증한다.
- 핵심 가치: 개인 구성 → 설명 가능한 추천 → 오래 남는 여행 아카이브.

## 2. 문제 정의와 지역 연계

방문객이 관심 장소를 여러 안내에서 찾은 뒤 직접 여행 내용을 모으고, 여행 후 메모와 경험을 따로 보관해야 한다는 문제 가설을 둔다. 지역·테마·동반 유형을 반영한 추천을 내 여행에 바로 담고 같은 화면에서 기록하면 준비와 회고가 쉬워지는지 검증한다. 인터뷰나 관찰로 검증된 수요라고 주장하지 않는다.

### 시흥시 내 거북섬 사례와 확장 근거


| 근거                                              | 자료의 시점·범위                                          | 프로젝트에 주는 의미                                                           |
| --------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 거북섬 상가 46개 동, 3,903개 점포의 공실률 74.2%  | 첨부 연구보고서 p.15, 2026년 4월 시흥시 내부 자료를 재인용 | 방문객의 활동이 주변 상점 이용으로 연결되도록 돕는 방안을 검토할 필요가 있다.  |
| 입점 상가 중 음식점 30.0%, 카페 10.2%             | 같은 보고서 p.15, 표 11                                    | 체험 이후 식음시설 방문을 연결하는 상품 구성을 검토할 지역적 근거가 있다.      |

| 상가 공실, 교통 접근성, 즐길거리 부족을 함께 검토 | 같은 보고서 pp.15–16                                      | 정보·이용 절차 개선만으로 공실과 교통 문제 전체가 해결된다고 주장하지 않는다. |

출처는 강영애·이진영, 시흥시정연구원, 『시흥 거북섬 투어패스 도입을 위한 검토 과제』, SHRI Issue Paper 제15호, 2026.06.30이다. [시흥시정연구원 발간 목록](https://www.shri.re.kr/research/policy/list)에서도 발간 사실을 확인했다. 위 수치는 보고서에 제시된 당시 현황이다.

보고서는 시흥시 전체의 현황 조사가 아니므로 거북섬의 공실률·시설 구성을 시흥시 전역에 적용하지 않는다. 보고서 p.29·표 23은 배곧·시흥시 전역으로의 단계적 확대를 검토안으로 제시한다. 이번 프로젝트는 사용자 요청에 따라 서비스 대상 지역을 시흥시 전체로 정하며, 지역별 수요·시설·이동 여건은 추가 조사한다.

본 프로젝트는 이 지역 현안 가운데 **여행 장소 선택·개인 구성·여행 후 기록의 연결**에 집중한다. 실제 상권 효과는 매력적인 제휴시설 확보, 상인의 참여 조건, 할인 비용 부담에 따라 달라지므로 서비스 시연 결과와 구분해 평가한다.

## 3. 해결방안과 차별성

관광 안내의 장소 정보를 개인 패스로 구성하고, 추천 이유를 확인하며 선택한 뒤, 방문 메모와 만족도를 같은 패스에 남긴다. 통합 이용권·지도·여행 기록 서비스가 이미 해결하는 기능을 새로운 기술로 주장하지 않는다. 기존 서비스에 기록 기능이 없다고 단정하지 않고, 시흥 방문 맥락에서 구성·추천·회고의 연결이 유용한지 비교한다.

온톨로지는 지역·장소·테마·동반 유형 관계로 추천 이유를 설명한다. 확인된 혜택 사용 피드백은 다음 추천에 반영한다. 직접 작성한 일반 장소 방문 기록은 인증 이력과 구분하고 추천 점수에 합산하지 않는다.

## 4. 핵심 기능과 범위

| 기능 | 사용자에게 제공하는 내용 |
| --- | --- |
| 나만의 여행 패스 | 이름·선택 날짜, 여러 패스 생성, 장소 추가·삭제·순서 변경 |
| 투어 내용 추천 | 지역·테마·동반 유형에 맞는 최대 3곳과 이유, 내 여행에 담기 |
| 여행 아카이브 | 방문 날짜·메모·만족도, 완료 여행 보관·복원, 지난 여행 다시 보기 |
| 선택 혜택 이용권 | 별도 발급·24시간 사용·본인 이용권 연결, 담당자 확인과 사용 피드백 |
| 관리·보안 | 자료 검토, 본인 기록 접근 통제, 기존 혜택 무결성·조건 보존 |

여행 패스는 만료되지 않으며 혜택 없이도 사용할 수 있다. 장소를 담는 행위는 예약·발급·사용을 뜻하지 않는다. 시연 이용권은 기존 1종·가상 혜택 2개를 유지한다. 상세 규칙과 제외 범위는 [요구사항](../spec.md)에만 둔다. 사진·공유·자동 동선은 첫 범위에서 제외한다.

## 5. 사용자 흐름

**로그인 → 여행 이름·날짜 설정 → 추천·이유 확인 → 장소 담기 → 순서 구성 → 방문 날짜·메모·만족도 저장 → 여행 완료·아카이브 → 지난 여행 다시 보기**.

추천 탐색은 로그인 없이 가능하다. 여행 상세에서 선택 혜택 이용권을 연결하고, 이용권 상세의 코드와 확인된 사용 이력으로 이동한다. 이용권 만료·취소 후에도 개인 여행 기록은 남는다. 직접 기록한 방문은 방문 인증으로 표시하지 않는다.

아카이브에서도 메모를 수정할 수 있다. 장소 구성을 바꾸려면 구성 중으로 되돌린다. 담당자·관리자는 개인 여행 메모를 열람하지 않는다. 모바일 폼은 이름·날짜·선택·버튼 중심으로 제공한다.

## 6. 기술과 데이터

[기술 스택](../plan.md#기술-스택)과 [MVC](mvc-design.md)를 따른다. Kotlin Spring MVC Controller는 요청을 처리하고 JSP는 화면을 표시하며, Service·JDBC·MySQL이 규칙과 저장을 담당한다. 화면과 API는 같은 서비스를 호출한다.

여행 패스·장소 기록은 혜택 이용권과 별도 저장한다. 부모 여행 행 잠금과 장소 유일 제약으로 중복 담기·순서 변경을 처리한다. 장소명·지역·위치·자료 구분을 담을 때 보존하므로 이후 관리 변경으로 아카이브가 사라지지 않는다. 기존 DB는 데이터 삭제 없이 추가 마이그레이션한다.

장소 자료는 [수집 안내](tourism-data.md), 출처와 지역 문제 근거는 [조사](research.md), 추천 규칙은 [의미 모델](tourism-semantics.md)에 둔다. 외부 API·지도·AI 호출 없이 자체 검토 자료로 핵심 흐름을 시연한다. 실제 장소 소개는 제휴·영업·예약 가능성을 뜻하지 않는다.

| --- | --- | --- |

## 8. 검증·기대효과·운영

방문객 3명 이상에게 여행 생성·추천 담기·순서 변경·기록·아카이브 재조회의 성공 여부·시간·오해를 관찰한다. 여행 패스와 24시간 이용권의 구분, 직접 방문 기록과 담당자 확인 이력의 구분도 확인한다. 담당자 2명 이상에게는 기존 혜택 사용 절차를 검증한다. 중대한 오해는 수정 후 재확인한다.

자동 검사는 본인 소유권·역할·CSRF·입력 검증·중복 담기·순서·장소 정보 보존·기록 보존과 기존 혜택 동시성을 확인한다. 실행 명령은 [README](../README.md#테스트), 미완료 검증은 [계획](../plan.md#남은-검증)에 둔다.

계획과 기록의 연결이 장소 선택과 재방문 준비를 도울 것으로 기대하지만 실제 이용률·상권 매출 효과는 별도 현장 검증이 필요하다. 수업 중에는 팀이 로컬 환경·자료 검토·백업을 담당한다. 상용화 시 운영 주체, 제휴와 비용, 개인정보 보관·삭제 기준을 별도로 합의해야 한다. 기관 참여나 정책 채택은 확정되지 않았다.

## 발표 구성

5분 가정: 문제·지역 맥락 45초, 핵심 가치 35초, 여행 생성→추천 담기→방문 기록→아카이브 시연 100초, 기술·역할 60초, 검증·활용 60초. 실제 배정 시간에 맞춘다.

발표 중심 문장: **“시흥의 가고 싶은 곳을 나만의 패스에 담고, 다녀온 경험을 오래 간직합니다.”**
